The boundary

A post-render step with a clear job.

Helm still renders the chart. The renderer changes only selected workload manifests and adds the Agent configuration they need.

01
⌁

Select

Match a workload by name, namespace, labels, or annotations. Exclusions always win; an empty target list injects nothing by default.

02
⇢

Render

Generate one deterministic ConfigMap per workload, then add Agent containers, projected auth, a checksum, and a memory-backed volume.

03
◈

Retrieve

After deployment, Vault Agent authenticates through the Pod’s ServiceAccount and writes secret files inside the Pod. Values stay out of the ConfigMap.

Start here

Build once. Place it after Helm.

The executable reads a multi-document YAML stream from stdin and writes valid Kubernetes YAML to stdout. Diagnostics stay on stderr.

See the example configuration ↗
terminalHelm 3.1+
# Build the renderer
go build -o vault-renderer ./cmd/vault-renderer

# Helm supplies manifests on stdin
export VAULT_RENDERER_CONFIG=./vault-values.yaml
export VAULT_RENDERER_NAMESPACE=production
helm upgrade --install payment ./chart \
  --namespace production \
  --post-renderer ./vault-renderer

Compatibility

The same renderer. Three Helm paths.

Helm changed its post-renderer interface across major versions. Each path keeps the renderer’s stdin/stdout contract intact.

02rendered chart

Helm 2

Helm 2 has no post-renderer. Pipe helm template into vault-renderer helm2-chart, then install the generated v1 chart as a Helm release.

Read the Helm 2 flow ↗
03direct executable

Helm 3

Pass the binary path directly to --post-renderer. Helm includes the transformed manifests in install, upgrade, and rollback history.

Read the Helm 3 flow ↗
04plugin manifest

Helm 4

Install the small postrenderer/v1 manifest, then pass its name to --post-renderer. The core binary remains independent of Helm.

Trust boundary

Configuration in the ConfigMap.
Secrets in memory.

The renderer never contacts Vault. It generates the instructions and mounts; Vault Agent does the authentication and retrieval after the Pod starts.

Read the local test record ↗
◇

Generated ConfigMap

Vault address, Kubernetes auth role, HCL, and template expressions. No retrieved values or tokens.

◉

Inside the Pod

Projected ServiceAccount token for the Agent and a memory-backed volume for rendered secret files.

✓

TLS by default

HTTPS is required unless HTTP is explicitly enabled for local testing. A private-CA path was verified in Kubernetes.
